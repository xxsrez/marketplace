# Краткая справка о режимах

Применяет `IG-HELP-01`. Читай этот reference только для чистого справочного
запроса о режимах Issue Grinder: он не начинает delivery и не требует загрузки
полного execution protocol.

## Правило ответа

Ответь на языке пользователя и соразмерно вопросу. Для общего запроса назови
четыре режима, default resolver и одно существенное отличие каждого режима. Для
узкого вопроса ответь только о нужных режимах, но не скрывай отличие, которое
может изменить выбор пользователя.

Справочный запрос не разрешает Task Manager scope, не создаёт Goal, не меняет
название Codex task, не обращается к Task Manager и не вызывает subagents либо
Strategic Explainer. Если тот же prompt ещё и явно поручает delivery, кратко
объясни или назови выбранный режим, затем обрабатывай delivery как отдельную
часть запроса по основному workflow.

## Четыре режима

- `Соло` — текущая основная модель последовательно выполняет всю delivery-работу
  Issue Grinder по одному issue или пакету без рабочих субагентов; отдельные
  service/provider agents не считаются исполнителями режима; нужен terminal
  result либо настоящий blocker.
- `Классический` — текущий основной агент делает почти всю работу сам; Luna получает
  только тривиальные, строго ограниченные и объективно проверяемые пакеты;
  один независимый Luna reviewer проверяет exact candidate даже на простом
  scope; режим терминальный.
- `Баланс` — текущий основной агент координирует и выполняет обычную работу;
  Sol Extra High решает сложные участки и независимо проверяет каждый кандидат;
  режим терминальный.
- `Экономичный` — текущий агент с Luna Max субагентами сохраняет один
  проверяемый candidate с независимой Luna-проверкой перед terminal acceptance;
  это единственный режим, который может честно
  остановить текущую попытку на resumable checkpoint без ложного `Done`.

## Режим по умолчанию

Для нового прогона без явного выбора всегда используется `Соло`.
`Классический` и `Баланс` включаются только по явному указанию пользователя.
`Экономичный` включается только явно. Объём и число задач не влияют на выбор.
Issue Grinder не определяет model/effort основной сессии и не требует доступа
к её журналам или настройкам; любой выбранный режим доступен без знания профиля.
Профили субагентов сохраняются: Luna Max для обычных ролей, Sol xhigh для
specialist и итогового reviewer в Балансе. Координатор — текущий основной агент.
Продолжение сохраняет режим; смена требует явной команды и сохранения работы.

## Быстрый выбор

- Нужны ровно текущая модель, последовательная delivery-работа и ноль рабочих
  subagents Issue Grinder — `Соло`.
- Нужна максимальная обычная уверенность без массовых альтернатив —
  `Классический`.
- Нужна экономия Sol при его независимой технической проверке — `Баланс`.
- Проверяющий профиль дефицитен и приемлем честный возобновляемый checkpoint —
  `Экономичный`.

Режим не меняет scope, authority, Production prohibition, Task Manager
lifecycle, требования к evidence или изоляции изменений.
